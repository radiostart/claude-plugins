# learn — 기재 규격 (무엇을 적고 무엇을 소스에 맡기는가)

`/pilot:learn` Phase 3 (추출) 과 Phase 4 (기록) 이 공유하는 기재 규격.
산출 **구조**는 자유지만 ([SKILL.md](../SKILL.md) § 제약 — MANIFEST 가 discovery
contract), **무엇을 적는가**는 본 규격을 따른다. knowledge-sync 의 환류 문안도
같은 규격을 쓴다 ([knowledge-sync.md](../../context/lifecycle/knowledge-sync.md) § 기록).

---

## 기재 층위 — L1 / L2 / L3

learn 산출물은 **소스로 가는 지도**다 — 코드를 읽지 않아도 되게 만드는 문서가
아니다. 구현의 SSOT 는 소스다.

| 층위 | 내용 | 처리 |
| ---- | ---- | ---- |
| **L1 위치** | 파일·심볼 경로, 클래스↔테이블 대응, 라우트↔핸들러, 호출처·정의처 | 기록 |
| **L2 계약·함정** | 호출 시그니처 (심볼·인자 형태·반환 형태), 상태값·enum, 트랜잭션 경계, 암묵 필터 (default_scope 류), 콜백 부작용, 소유권, 이름과 다른 실제 책임 | 기록 |
| **L3 구현** | 계산식·수식, 분기 조건의 순서·임계값, 반환 키·생성 필드 전수 목록, 쿼리 체인 전문, 코드 블록 전사 | **기록 안 함** — L1 로 대체 (`로직 상세는 {심볼 앵커} 에서 파악`) |

**2 차 필터 (휘발성)** — 판정 문답 "이걸 모르는 다음 planner 가 잘못된 계획을
세우는가" ([knowledge-sync.md](../../context/lifecycle/knowledge-sync.md) § none —
노이즈 가드) 는 **유용성만** 본다. 유용성으로 통과한 항목에 한 번 더 묻는다:
**"다음 릴리즈에 이 코드가 바뀌면 이 문장이 틀리는가?"** 틀리면 L3 다 — 유용해도
적지 않고 위치만 남긴다. 계산식은 유용성과 휘발성이 동시에 최대인 전형이라
유용성 문답만으로는 반드시 통과한다.

- L3 를 적으면 셋이 동시에 깨진다: ① 도메인 진입 문서는 orchestrate-load 가 매
  에이전트 호출마다 로드하므로 토큰을 영구 지불한다 ② 코드가 바뀌면 문서가
  조용히 오답이 된다 — 인용을 따라가지 않고 문서를 믿는 소비자가 틀린다 ③ 문서를
  신뢰한 다음 사용자가 소스를 열지 않아 실제 조건 분기를 놓친다.
- **L3 금지는 부재 주장이 아니다** — `계산식 없음` 이 아니라 **`여기에 있다`** 를
  적는 것이므로 § 부재 주장 반증 의무의 대상이 아니다.
- **기재 범위 고지** — L3 를 소스에 맡긴 영역이 있으면 산출물 상단에 1 줄 남긴다:
  `> 기재 범위: {영역} 의 처리 로직은 {심볼 앵커} 에서 직접 파악한다 — 본 문서는
  위치와 함정만 기록한다.` 고지가 없으면 다음 사용자는 "문서에 없으면 그런 처리가
  없다" 로 읽는다 (§ Routes 표 선별 기재의 고지 의무와 같은 이유).

## Routes 표 — 선별 기재

Routes 표를 만드는 산출 구조라면 (구조 자유 — 표 없는 구조면 해당 없음) 라우트를
전수 나열하지 않고 **선별 기재**한다. 도메인 진입 문서는 매 에이전트 호출마다
상시 로드된다 — 라우트 목록을 그대로 복제하면 매 호출 토큰을 쓰면서도 커버리지는
코드 변경에 뒤처지고, 다음 사용자가 "표에 없으면 라우트가 없다" 로 오판한다.
표는 라우트 색인이 아니라 **경로만 봐서는 알 수 없는 것**의 목록이다.

- **넣는다**: ① 쓰기·상태 변경 계열 (생성·수정·삭제·승인·취소·일괄 처리) ② 경로만으로
  동작을 알 수 없는 것 ③ 도메인 기본 경로 밖의 예외 경로 ④ 액션·핸들러명이 경로와
  다른 것 ⑤ 권한·인가 코드가 나머지와 다른 것.
- **넣지 않는다**: 목적 컬럼이 경로·핸들러명의 재진술에 그치는 행 (`GET /orders` →
  "주문 목록 조회"). 인용을 따라가면 같은 정보가 나오므로 값 없이 행만 늘린다.
  단 행을 빼더라도 **그 핸들러 파일의 인용은 문서에 남는지 확인**한다 — 도메인
  문서의 인용 경로는 boundary 호출처 수집의 입력이다
  ([cross-domain.md](cross-domain.md) § Boundary 모드 1. 호출처 수집).
- **고지 의무** — 표 바로 위에 3 줄을 병기한다 (인용문 권장): ① 선별 기준 1 줄
  ② `이 표에 없다는 것은 라우트가 없다는 근거가 아니다` ③ 전수 조회 수단 1 줄.
  - ③ 은 아래 우선순위로 **직접 확인한 것만** 적는다. 1 순위는 프레임워크의
    **라우트 열람 CLI** (`bin/rails routes`·`manage.py show_urls`·`php artisan
    route:list` 등) — 정의 파일을 읽는 것보다 정확하다 (동적 정의·엔진·mount 까지
    전개된 결과). 도메인 범위로 좁힌 형태로 적는다 (예: `bin/rails routes | grep
    admin/orders`). 2 순위는 라우트 정의 파일이 소스 범위 안일 때 그 경로와 Grep
    구문 (예: `config/routes.*` 에 `^\s*(get|post|put|patch|delete)\s`). 둘 다
    확인하지 못하면 사용자에게 확인받은 것만 적고, 그것도 없으면 ③ 을 생략하고
    ①② 만 남긴다 (미검증 명령 기재는 추측 금지 위반).
  - **CLI 는 실행해 확인한 것만 적는다** — 프레임워크를 보고 "있을 것" 으로 추정해
    쓰지 않는다. 금지되는 것은 확인하지 않은 안내이지 명령 형식이 아니다. 실행은
    읽기 전용 열람 명령 1 회로 제한하며 (쓰기·마이그레이션·서버 기동·패키지 설치
    금지), 실패·환경 의존 (DB 접속·env 부재) 시 재시도·우회 없이 다음 순위로
    내려간다.
  - **실행 시점·건수를 병기한다** — 적어둔 명령을 **그대로 실행했을 때의 결과
    건수**와 실행 날짜 (ISO) 를 함께 남긴다 — 예: `전수 조회: bin/rails routes |
    grep admin/orders (2026-08-25 기준 108건)`. 표 행수와 대비되어 이 표가 어느
    정도의 부분집합인지 즉시 드러나고, 다음 갱신 때 증감이 drift 신호가 된다.
    날짜는 프로젝트 식별자 배제 대상이 아니다 (배제 대상은 feature ID·티켓 키·
    PR#·스프린트 라벨). ③ 을 생략한 경우 시점·건수도 적지 않는다.
- **적용 범위는 라우트 표 한정** — Models·Services 류 표는 행을 빼지 않는다.
  클래스명 목록과 인용 경로는 boundary 모드 호출처 수집·MANIFEST 외부 도메인
  reference 판별의 대조 입력이다 ([cross-domain.md](cross-domain.md)). 아래
  목적 컬럼 규율이 다루는 것은 **컬럼의 내용**이지 행의 존폐가 아니다.

## 목적 컬럼 — 이름 재진술 금지

- **Services 류**: `OrderCancelService` → "주문 취소 서비스" 는 클래스명을 옮겨
  적은 것이라 정보가 0 이다. **이름으로 짚으면 틀리는 것**만 적는다 — 소유권
  (어느 도메인·화면이 실제로 쓰는지), 이름과 다른 실제 책임, 클래스명 오타·낡은
  명명, 자체 트랜잭션 개시 여부. 적을 것이 없으면 **목적 칸을 비운다** (빈칸이
  재진술보다 정직하다 — 페르소나 "추측은 빈 칸으로 둔다").
- **Models 류**: 동일 규율. 모델에서 "이름으로 틀리게 짚는 것" 은 주로 실제 저장
  대상 (테이블명이 클래스명과 다름), soft delete·기본 스코프 같은 암묵 필터,
  자체 트랜잭션 개시다.
- **비우더라도 인용은 남긴다** — 인용을 목적 칸에 인라인으로 쓰던 표라면 별도
  인용 컬럼으로 옮긴 뒤 비운다. 인용 없는 행은 추측 의심 대상이 되고
  ([heuristics.md](heuristics.md) § 안티 패턴), 그 행의 소스 경로가 boundary
  호출처 수집의 입력 목록에서도 빠진다.

## 멀티 DB — 귀속 추정 금지 + 전수 대조

커넥션이 여럿인 코드베이스에서 모델이 어느 DB 에 속하는지를 **화면 계열·클래스명·
호출 문맥으로 추정하지 않는다** — 어떤 화면에서 쓰이는지, 어떤 도메인의 메서드가
호출하는지는 그 모델의 커넥션 근거가 아니다.

- 판정 근거는 둘로 고정한다: ① 모델의 base class·커넥션 선언
  (`establish_connection`·DataSource·persistence unit 등 언어별 선언) ② 해당
  테이블이 실린 스키마 덤프의 소재. 둘로 확정되지 않으면 DB 칸을 `(미확인)` 으로
  남긴다.
- **표를 확정하기 전에 base class 를 전수 대조한다** — 표의 클래스명을
  alternation 으로 묶어 **배치 Grep 1 회**로 base class·커넥션 선언을 회수하고
  표의 DB 칸과 대조한 뒤 확정한다. 네임스페이스 모델 (`Wms::Box` 류) 은 짧은
  이름으로 한 번 더 돌린다. 회수되지 않은 클래스는 추정하지 말고 `(미확인)`.
  - 예 (Ruby/Rails): `grep -rhoE "^\s*class (ClassA|ClassB|…) < [A-Za-z:]+" {models 경로}`
  - 비용은 **주장 수와 무관하게 Grep 1~2 회**다. 주장 수만큼 Grep 하지 않는다.
  - **표에 값이 이미 적혀 있어도 생략하지 않는다** — 추정 금지 조항은 빈 칸을
    채울 때만 발동하므로 이미 적힌 오기는 걸러내지 못한다. `--force` 갱신
    실행에서도 동일하게 돌리고, 대조 불일치가 나오면 미리보기에 **정정 전/후를
    함께** 제시한다.
- 오기의 영향: 마이그레이션 경로·base class 선택·raw SQL 의 DB prefix 가 전부
  틀린다. 더해 **다른 DB 의 트랜잭션이 이 모델을 보호한다고 오독**한다 —
  커넥션이 다르면 같은 트랜잭션이 아니므로 롤백 가정이 깨진다.

## 부재 주장 — 반증 의무

`전용 서비스 없음`·`호출처 0 건`·`dead code`·`선언만 존재` 류는 존재 주장보다
비싸다. 존재는 인용 한 줄로 서지만 부재는 범위 전체를 봐야 서고, 틀리면 다음
사용자가 **이미 있는 것을 새로 만드는 계획**을 세운다.

- 진입점·추적 depth 안만 보고 "없다" 고 쓰지 않는다. 소스 범위 전체를 대상으로 한
  **패턴 지정 Grep** 으로 반증을 시도한다. 근거가 소스 범위 밖에 있어야 확인되면
  (뷰 템플릿·프런트엔드 자산·설정) 사용자에게 범위 확장을 요청한다.
- **표기를 최소 2 가지로 시도한다** — 심볼명 그대로, 그리고 언어 컨벤션 변환형
  (snake_case 연관 호출·약어가 분해된 파일명 등). 한 표기의 0 건은 부재의 근거가
  아니다 ([cross-domain.md](cross-domain.md) § Boundary 모드의 약어 Glob 재확인과
  같은 이유).
- **반증 범위를 함께 남긴다** — `전용 서비스 확인되지 않음 (범위: 소스 전역 Grep —
  클래스명·snake_case 연관 호출, 0 건)`. 범위 없는 부재 주장은 다음 사용자가
  재검증할 수 없어 그대로 신뢰하거나 통째로 다시 조사하는 수밖에 없다.
- 확인이 안 되면 `없다` 가 아니라 **`코드에서 확인되지 않음 (범위: …)`** 으로
  적는다 — 둘은 다른 주장이다.
- **빈칸은 부재 주장이 아니다** — § 목적 컬럼의 "적을 것이 없으면 비운다" 는
  "특기할 것이 없다" 는 표시이므로 반증 의무가 없다.

## 소스 인용 규격

모든 추출 항목은 소스 인용을 남긴다 — 표의 각 행은 마지막 컬럼 또는 별도 인용
컬럼에 단다. 세 형식을 쓴다:

- **심볼 앵커 `` `file#symbol` `` — 가리킬 심볼이 있으면 이쪽을 쓴다.** 메서드·
  scope·상수처럼 이름이 있는 지점은 코드가 위아래로 밀려도 앵커가 살아남는다.
  라인 번호는 다음 커밋이면 어긋나기 시작해, 인용이 많아질수록 "틀린 위치를
  가리키는 인용" 이 쌓인다.
  - 예: ``취소 시 재고 복원 (`app/services/order_service.rb#cancel!`)``
  - 예: ``| Order | orders | soft delete 기본 스코프 | `app/models/order.rb#default_scope` |``
- **`file:line`** — 심볼로 짚을 수 없는 지점에 쓴다 (설정 라인, 스키마 덤프 행,
  이름 없는 블록 내부). 예: `(config/state_machine.yml:42)`.
  - **라인 범위 (`file:100-160`) 는 쓰지 않는다** — 범위 인용은 대개 그 블록을
    본문에 옮겨 적었다는 신호이고 (§ 기재 층위 L3), 옮기지 않았더라도 다음
    커밋이면 양끝이 함께 어긋난다. 블록을 가리켜야 하면 그 블록을 감싼 심볼
    앵커를 쓴다.
- **경로만** (`` `app/models/order.rb` ``) 도 유효한 인용이다 — 파일 전체가
  근거일 때 억지 앵커를 붙이지 않는다.
- **인용은 백틱 또는 괄호로 감싼다** — 세 형식의 래핑이 통일돼야 사람·도구
  모두 산문과 인용을 구분할 수 있다 (인용 drift 검사를 도입할 때의 기계 인식
  전제이기도 하다).
