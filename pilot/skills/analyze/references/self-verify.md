# 7 단계: 분석 품질 자가 검증

6-5 (doctor) 는 스키마·구조 검증이다. 이 단계는 **분석 내용 자체** 의 품질을 Claude 가 직접 재검사한다.

아래 4 항목을 순서대로 확인한다. 전원 PASS 면 한 줄 요약, 하나라도 FAIL/WARN 이면 항목별 상세 + 권장 조치를 **결과 출력 (8 단계) 앞에** 먼저 표시한다.

> `--regen-agents` 모드에서는 7-1, 7-4 를 건너뛴다 (docs → features 재변환이 없으므로 해당 없음). 7-2, 7-3 만 수행.

## 7-1. 커버리지

- 대상 원본 파일의 H2 섹션 목록을 Grep (`^##`) 으로 수집.
- 키워드·파일 지정 모드일 때는 **이번 턴 대상 섹션** 집합으로 한정 (관련 없는 섹션은 제외 — 스킵은 정상 동작).
- features/ 파일 상단 `> source:` 와 원본 H2 를 매핑하여 누락 섹션 목록 산출.
- 누락 0 건 → PASS. 1 건 이상 → 누락 섹션 나열 + `--force` 또는 키워드 재실행 안내.
- 메인 2 단계에서 Read rejection 으로 일부 섹션을 못 읽은 경우, 범위 보고를 이 단계에서 재확인한다.

## 7-2. 구조 완성도

각 features/*.md (`.plan.md`·`.plan.critic.md`·`.auto.md`·`.eval.md` 제외) 에 아래 섹션이 존재해야 한다:

- 필수: `## 요구사항`, `## 비즈니스 규칙`, `## 예외 케이스`
- 선택: `## 상태 전환` (상태값 변화가 있는 기능만)

필수 섹션 누락 또는 섹션 본문 공백 → FAIL. 대상 파일·누락 섹션 목록 보고.

## 7-3. 정합성

아래 3 값이 일치해야 한다:

- `features/*.md` 개수 (`.plan.md`·`.plan.critic.md`·`.auto.md`·`.eval.md` 제외)
- `project.md` 의 `## 목표` 체크리스트 항목 개수
- `.agent-state.yml` 의 `last_analyzed_features`

불일치 → FAIL. 세 값을 모두 표시하고 메인 5-1 / 6-4 단계 재확인 안내.

## 7-4. 추측 혐의

features/ 본문에 아래 패턴이 있으면 WARN (원본에 없는 내용을 채웠을 가능성):

```
TBD | TODO | (예상) | (추정) | 미정 | 확인 필요 | ??
```

해당 파일·라인 번호를 Grep 으로 보고한다. 원본 docs 에 실제로 존재하는 표기면 사용자 판단 하에 무시 가능 — 삭제 여부는 사용자에게 묻고 자동 제거하지 않는다 (자동 제거 시 사용자가 의도한 TODO 까지 사라져 정보 손실).

---

## 검증 결과 출력 형식

- 전원 PASS: `analyze-verify: all checks passed` 한 줄.
- FAIL/WARN: 항목별로 아래 형식 — `결과 출력 (8)` 앞에 먼저 표시한다.

  ```
  analyze-verify:
    7-1 커버리지 (FAIL): 누락 섹션 2개
      - docs/xxx.md > "주문 취소" 섹션
      - docs/xxx.md > "환불 처리" 섹션
      권장: /pilot:analyze --force 또는 키워드 재실행
    7-2 구조 (PASS)
    7-3 정합성 (PASS)
    7-4 추측 혐의 (WARN): 1건
      - features/07-xxx.md:23 — "(예상)" 표기
      권장: 원본 재확인 후 수동 수정
  ```

WARN 만 있으면 진행한다. FAIL 이 있으면 사용자에게 재실행 여부를 먼저 묻고 8 단계로 넘어간다 (자동 재분석 금지 — 사용자 확인 경로 유지).
