# Commit 가이드

커밋 실행 전 미스테이지 파일 확인 및 커밋 메시지 작성 규칙.

---

## 커밋 전 흐름

### 1. 미스테이지 파일 확인

`git status`로 staged되지 않은 파일을 확인하고, **파일별로 포함 여부를 사용자에게 질의**한다.

- 한 번에 모아서 물어보지 말고, 파일(또는 관련 파일 묶음)을 나열한 뒤 어떤 것을 포함할지 확인
- 명백히 이번 작업과 무관한 파일(예: 다른 기능, 임시 파일)은 별도로 언급

질의 형식:

```
스테이지되지 않은 파일이 있습니다:

- {source_root}/services/order_service.{ext}
- {source_root}/views/admin/orders/index.{ext}
- workspace/projects/MyProject/agents/generator.md

포함할 파일을 알려주세요. (전체 포함 / 일부 선택 / 제외)
```

### 2. 커밋 메시지 작성

확인된 변경 내용을 바탕으로 아래 규칙에 따라 메시지를 작성한다.

---

## 커밋 메시지 규칙

### 기본 형식

```
{scope}: {한국어 설명}
```

또는 티켓이 있는 경우:

```
[{티켓번호}] {한국어 설명}
```

### scope 기준

| scope      | 사용 시점                                          |
| ---------- | -------------------------------------------------- |
| `feat`     | 신규 기능                                          |
| `fix`      | 버그 수정                                          |
| `refactor` | 기능 변경 없는 코드 개선                           |
| `skills`   | workspace/ 문서 작업 (프로젝트·이슈 설정)             |
| `{기능명}` | 특정 기능에 국한된 변경 (예: `order`, `invoice`) |

scope 없이 한국어 설명만으로도 무방하다 (단순 수정, 문서 작업 등).

### 작성 원칙

- **한국어**로 작성한다
- 제목은 **50자 이내**가 이상적
- 변경 범위가 크거나 맥락이 필요한 경우 본문(body)을 추가한다
- `wip` 커밋은 이후 squash 예정인 작업에만 허용

### 예시

```
skills: 프로젝트 단위 Harness 구조 도입 (Orchestrator + agents/)

[TICKET-123] 주문 상태 전환 시 취소 제한 추가

order: 주문 접수 모달 상태별 UI 분기 구현

목록 노출 조건 추가
```

---

## 주의사항

- credentials/secrets 파일 (`.env`, `*.key`, `*credentials*` 등) 은 절대 포함하지 않는다
- workspace/ 변경과 코드 변경은 **가능하면 분리**하여 커밋한다
- 푸시 전 브랜치 확인 (`git branch`) — `main`/`develop` 직접 푸시 금지
