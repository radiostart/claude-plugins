# 조건부 인터뷰 — Open Questions 소비 규칙

`/pilot:create-feature` 와 `/pilot:analyze` 가 공유하는 조건부 인터뷰 규칙. feature spec 의 `## Open Questions` 에 남은 unchecked 항목을 소비(질의·반영)하는 절차의 SSOT — [`open-questions.md`](open-questions.md)(작성 규칙)와 짝을 이룬다.

---

## 발동 조건 (soft gate)

대상 spec 의 `## Open Questions` (H2 정확 매칭 `^## Open Questions\s*$`, 코드블록 펜스 안 등장은 무시) 하위에 `- [ ] ` prefix 행이 1 개 이상 존재할 때만 발동한다. `- (없음)` 또는 `- [x]` 행뿐이면 무발동 — 현행과 완전히 동일하게 무중단 진행한다.

**인터뷰는 게이트가 아니다** — 어떤 실패·스킵도 호출 스킬(`/pilot:create-feature`·`/pilot:analyze`)의 본 흐름을 중단하지 않는다.

---

## 행 파싱 규칙

unchecked 판정은 `- [ ] ` prefix 만 기준으로 한다. [`open-questions.md`](open-questions.md) 의 행 본문 형식은 3 종이 혼재한다 — colon 형(`- [ ] {질문}: ...`), 화살표 포함 (b) 자동 행(`→` 포함), 자유형 (c) 자동 행. `: ` 구분자에는 의존하지 않는다.

체크 반영 형식: `- [x] {원문 그대로} → {답변 요약}` — 원문을 보존하고 ` → {답변 요약}` 을 1 회 append 한다. (b) 자동 행처럼 원문에 이미 `→` 가 포함된 경우에도 **마지막 `→` 뒤 = 답변 요약** 규약으로 충돌 없이 판독한다.

**체크된 (b) 행은 재detect 의 재추가 대상이 아니다.** 동일 외부 도메인을 가리키는 `### (b)` 행이 이미 존재하면, 체크 상태(`- [x]`)·답변 append 여부와 무관하게 중복으로 skip 한다. 이 중복 판정 기준(판정 키 = 외부 도메인명)의 SSOT 는 [`scope-sync.md`](../../analyze/references/scope-sync.md) 5-2 규칙 2 — 상세 근거는 그 문서를 참조한다.

---

## 산출물 대조 (경량 갭 체크)

질의 전 1 회, spec 의 핵심 심볼(상태값·메서드·필드·클래스)을 `workspace/context/scope/{domain}.md` 산출물에서 lookup 한다.

- **`{domain}` 은 `.agent-state.yml.domain` 만 사용한다.** null 이면 대조를 스킵한다(A2) — 도메인 결정을 인터뷰 단계로 앞당기거나 자체 추론하지 않는다.
- **대조 대상은 spec 본문에 명시 기재된 심볼만.** 유추 심볼은 금지한다.
- 대조로 `### (a)` 에 추가하는 행 수도 질의 상한과 동일한 상한(단건 4 / 일괄 8)을 넘지 않는다 — 초과하는 부재 심볼은 행 추가 자체를 하지 않는다(spec 오염 방지).
- 부재 심볼은 `### (a) 같은 도메인 추가 read 필요` 에 `- [ ] {심볼}: scope/{domain}.md 미기재 — 실제 위치·시그니처 확인 필요` 행을 추가한 뒤 인터뷰 대상에 포함한다.
- **코드베이스 Grep/Read 탐색은 금지한다** — 심층 영향 분석은 `@pilot-planner` 의 책임이다(역할 중복 금지).

> **A2 runtime fallback**: `scope/{domain}.md` 부재·빈 파일 → 대조 스킵, 기존 unchecked 항목만으로 인터뷰 진행. abort 하지 않는다.

---

## 질의 규칙

우선순위: **(d) 비즈니스 결정 > (b) cross-domain 산출물 부재 > (c) 외부 시스템 spec 부재 > (a) 같은 도메인 추가 read**.

동일 카테고리 내 정렬: (단건 — create-feature) 파일 내 등장 순 / (일괄 — analyze) 파일 NN 순 → 파일 내 등장 순.

상한: 단건 최대 4 문항 / 일괄 최대 8 문항. 산출물 대조로 추가된 (a) 행도 상한 카운트에 포함한다((a) 가 최하위 우선순위라 초과 시 자연스럽게 미질의로 밀린다). 초과분은 질의하지 않고 `미질의 N건` 으로 리포트한다.

모든 질문에 **"나중에 결정"** 을 항상 제공한다. 질의는 메인 대화(스킬 실행 컨텍스트)에서만 수행한다 — 서브에이전트·autopilot 은 인터뷰를 수행하지 않는다(답변 전달은 spec 파일 경유).

---

## 답변 반영

카테고리 → spec 섹션 매핑:

| 카테고리 | 반영 섹션 |
| --- | --- |
| (d) 비즈니스 결정 | `## 비즈니스 규칙` (요구사항 성격이면 `## 요구사항`) |
| (b) cross-domain 산출물 부재 | `## 요구사항` 또는 `## 예외 케이스` |
| (c) 외부 시스템 spec 부재 | `## 요구사항` 또는 `## 예외 케이스` |
| (a) 같은 도메인 추가 read | 해당 심볼이 언급된 섹션 |

**답변 원문 요지만 반영한다 — 답변에 없는 내용의 추측 보강은 금지한다**(analyze 의 추측 금지 원칙과 동일 축). 스킵한 항목은 spec 무변경 + unchecked 유지.

## 결과 리포트

`인터뷰: 해소 N건 / 이월 M건` (상한 초과 시 ` / 미질의 K건` 추가).

산술 규약:

- **N** = 답변으로 해소되어 `- [x]` 로 체크된 항목 수.
- **M** = 질의 후 "나중에 결정" 으로 스킵된 항목 수 (K 불포함).
- **K** = 상한 초과로 질의되지 않은 항목 수.
- **N + M + K = 발동 대상 unchecked 총수** (산출물 대조로 추가된 행 포함).

무발동 시 라인 자체를 생략한다 — 현행 출력과 동일(무중단 보장).

---

## 미발동 컨텍스트

다음 상황에서는 조건부 인터뷰가 발동하지 않는다:

- `/pilot:analyze --regen-agents` — features 신규 생성이 없는 모드.
- 에이전트 4 종(`@pilot-planner`·`@pilot-planner-critic`·`@pilot-generator`·`@pilot-evaluator`)과 `/pilot:autopilot` — 무변경. 인터뷰 결과는 spec 파일 경유로만 전달된다(서브에이전트는 사용자 질의 불가).
