# 구현 질의 (ask)

구현된 기능의 동작·위치에 대한 질문에 **도메인 컨텍스트 → 소스** 순의 고정된 탐색 경로로 답하는 읽기 전용 질의입니다.

## 전제 조건

- 없음 — 활성 작업이 없어도, `workspace/context/` 가 비어 있어도 동작합니다 (컨텍스트 부재 시 degrade 고지 후 소스만으로 답변).
- 코드 **수정·구현 요청**은 대상이 아닙니다 ("바꿔줘"·"고쳐줘" 는 `/pilot:issue`·`/pilot:create-feature` 경로).

## 작업 절차

### 1. 질의

```
/pilot:ask 주문 취소 시 재고 복원은 어디서 처리돼?
```

탐색 순서:

1. **활성 작업 관련성** — 활성 project/issue 가 있으면 식별 표면 (목표 절·feature 파일명·issue H1) 만 대조해 관련 문서를 1차 컨텍스트로 로드. 불확실하면 로드하지 않습니다.
2. **도메인 컨텍스트** — `MANIFEST.md` 로 도메인 판정 → 진입 파일·`boundaries/` Read. MANIFEST 부재 시 종료하지 않고 "도메인 컨텍스트 없음" 1줄 고지 후 소스로 직행합니다.
3. **소스 확증** — 계산식·분기·조건 같은 세부는 반드시 소스에서 확인하고 `file:line` 으로 인용합니다. 컨텍스트 문서는 소스로 가는 지도이지 답의 근거가 아닙니다.

### 2. 답변 읽기

- **결론 먼저** (1~3문장) → 동작 설명 (소스 인용 기반) → 근거 출처 구분.
- 탐색 중 컨텍스트 문서와 소스의 불일치 (drift) 를 발견하면 보고 + `/pilot:learn` 갱신 제안만 합니다 — 직접 수정하지 않습니다 (읽기 전용 계약).
- 질문에 개선 의도 (가정형 — "바꾸면 어때" 류) 가 있으면 답변 말미에 개선안 절 + 실행 라우팅 (`/pilot:issue` / `/pilot:create-feature`) 을 덧붙입니다. 자동 실행은 없습니다.

같은 세션의 후속 질문은 스킬을 재호출하지 않고 이미 로드된 컨텍스트 위에서 직접 답합니다.
