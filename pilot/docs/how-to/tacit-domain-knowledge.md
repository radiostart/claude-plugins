# 도메인 암묵지 기록하기

!!! info "한 줄 요약"
    `/pilot:learn` 은 코드에 *명시된* 사실만 추출한다. 코드의 의도·비즈니스 맥락처럼 *암묵지* 로만 존재하는 도메인 지식은 사람이 — Claude 와 함께 — 끌어내 `context/` 에 기록해야 한다. 이 페이지는 *끌어내는 프롬프트 방법* 과 *무엇을·어떻게 기록할지* 를 다룬다.

## 왜 필요한가 — learn 이 못 잡는 것

`learn` 의 산출물은 코드에 *문자 그대로 있는 것* 이다 (시그니처·라우트·상태값, `file:line` 인용). 하지만 실제 도메인 지식의 상당 부분은 **암묵지** — 어디에도 명시돼 있지 않다:

- **코드에 있지만 의도가 안 보임** — 매직 넘버, 호출 순서 의존성, 이유 없는 분기. 코드는 *무엇* 을 하는지 보여주지만 *왜* 는 말하지 않는다.
- **코드 밖에만 있음** — 비즈니스 정책의 배경, 과거 결정·장애 대응, 도메인 용어의 진짜 의미, 담당자 머릿속에만 있는 제약.

이 암묵지가 빠지면 AI(와 신규 합류자)는 *그럴듯하지만 틀린* 판단을 한다. `learn` 은 "추측 금지" 원칙상 이걸 채우지 않는다 — 채우는 건 사람의 일이다.

## 전제

- `/pilot:learn` 으로 도메인 *구조* 가 부트스트랩돼 있다 ([외부 도메인 부트스트랩](cross-domain-learn.md)).

## 끌어내기 — Claude 와 함께

핵심 원칙: **Claude 에게 답을 지어내게 하지 말고, *질문을 만들게* 하라.** 암묵지의 답은 코드가 아니라 사람에게 있다. 좋은 프롬프트 패턴:

- **빈 칸 찾기** — "이 도메인 문서에서 코드만으로는 *왜* 인지 알 수 없는 지점을 표시하고, 도메인 전문가에게 물어야 할 질문 목록으로 만들어줘. 추측해서 답을 채우지 마."
- **인터뷰 생성** — learn 산출물을 주고 "이 코드의 비즈니스 의도를 확인하려면 어떤 질문을 해야 하나? 질문만 나열해줘."
- **초안 구조화** — 내가 아는 것을 거친 말로 설명한 뒤 "이걸 도메인 규칙 문서 형식으로 정리해줘. 내가 말 안 한 부분은 지어내지 말고 `_(추가 예정)_` 로 남겨."
- **용어 수집** — "이 코드에 나오는 도메인 용어 중 일반적 의미와 다르게 쓰일 법한 단어를 추려줘."

피해야 할 것:

- Claude 가 "아마 이런 이유일 것" 이라고 *그럴듯한 추측* 을 하게 두는 것 — 그럴듯함은 정확함이 아니다.
- 한 번에 완벽한 문서를 뽑으려는 것 — 암묵지는 작업하며 점진적으로 드러난다.

## 무엇을 기록할까

| 종류 | 예 |
|---|---|
| 비즈니스 규칙·정책 | "환불 7 일 제한" 의 *근거* 와 예외 |
| 도메인 용어집 | 같은 단어의 도메인 특화 의미 (도메인의 `정산` ≠ 회계의 `정산`) |
| 암묵적 제약·순서 | "A 를 호출하기 전 반드시 B" — 코드엔 강제 장치 없음 |
| 역사적 결정·예외 | "이 분기는 2023 마이그레이션 호환용 — 신규 코드는 쓰지 말 것" |
| 엣지 케이스·함정 | 빠지기 쉬운 함정, 과거 장애의 원인 |
| 외부 시스템 계약 | 문서에 없는 외부 API 의 실제 동작 |

## 어떻게 기록할까

- **출처를 남긴다** — `file:line` 인용, 또는 "PM 결정 2024-03", 또는 "확인: {담당자}". 출처 없는 단정은 다음 사람이 신뢰할 수 없다.
- **모르는 건 추측하지 않는다** — `_(추가 예정)_` 로 비워 두고, 확인되면 채운다. 빈 칸은 *정직한 상태* 다.
- **선언적으로** — 정책·제약을 산문·표로. 코드 복붙 금지.
- **알맞은 문서에** — 비즈니스 규칙은 [도메인 규칙 문서](authoring-domain-rules.md), 용어집은 도메인 문서 상단, 구조 사실은 `learn` 산출물.
- **MANIFEST 가 가리키게** — 새 문서는 `MANIFEST.md` 에서 발견 가능해야 에이전트가 로드한다.
- **점진적으로** — 작업 중 암묵지를 발견하면 그 자리에서 추가한다. 에이전트도 작업 중 발견 시 [Drift Protocol](../explanation/drift-protocol.md) 에 따라 *수정안을 제안* 한다 (직접 쓰지 않음).
