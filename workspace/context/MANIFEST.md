# Domain Manifest

도메인 지식의 진입점. 에이전트 (`@planner`·`@generator`·`@evaluator`) 와 스킬 (`/pilot:*`) 이 **탐색·코드 수정 전**에 이 파일을 먼저 읽는다.

> 이 파일의 **내용 구조는 자유롭게 정의한다.** 런타임 설정은 같은 폴더의 `config.md` 가 담당하고, 도메인 지식 파일들의 폴더 구조·파일명 컨벤션은 워크스페이스가 자유롭게 결정한다.
>
> 일반적으로 다음 정보가 포함되면 유용하다 — 강제는 아님:
>
> - 도메인 분류 (어떤 도메인이 있고 어떻게 식별하는가)
> - 도메인 판단 기준 (라우트·키워드·모델명 등)
> - 공통 모델·서비스 (도메인 횡단으로 자주 쓰는 것)
> - 교차 도메인 참조 규칙
>
> 표·산문·트리 등 표기 형식 자유. 첫 도메인 파일을 작성한 뒤 그 모양을 레퍼런스로 삼아 이후 파일을 통일하는 방식을 권장.

> **자동 로드 — 도메인 진입 파일** (선택)
>
> `## 도메인 분류` H2 + 3 컬럼 표 (`| 도메인 | 진입 파일 | 설명 |`) 로 작성하면 플러그인 (`orchestrate-load.py`) 이 wrapper 진입 시 해당 도메인의 진입 파일을 자동으로 로드한다. 진입 파일 경로는 `workspace/context/` 기준 상대 경로.
>
> 표 형식이 아니어도 (산문·리스트 등) MANIFEST 자체는 항상 로드되므로 에이전트가 자연어로 추적 가능. 표 형식은 자동 로드 단축이 추가되는 보너스.
>
> `/pilot:learn {진입점}` 으로 부트스트랩하면 표 형식으로 자동 등록한다.
